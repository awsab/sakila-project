📌 THE QUESTION YOU ASKED
═══════════════════════════════════════════════════════════════════════════════

"Why do we need to add all the services as dependencies in this module,
 actually each service will register itself with this module, right?"

✅ ANSWER:
   You are 100% CORRECT!

   Services should NOT be dependencies in eureka-registry.
   Each service registers itself via eureka-client dependency.


❌ BEFORE (INCORRECT APPROACH)
═══════════════════════════════════════════════════════════════════════════════

eureka-registry/pom.xml contains:
  ├─ eureka-server (Eureka registry)
  ├─ spring-cloud-gateway (API routes)
  ├─ springdoc-openapi-ui (Swagger docs)
  └─ ❌ catalog-service (WRONG - unnecessary dependency)
  └─ ❌ customer-service (WRONG - unnecessary dependency)
  └─ ❌ inventory-service (WRONG - unnecessary dependency)
  └─ ❌ rental-service (WRONG - unnecessary dependency)

Problems:
  ✗ Build coupling: registry build depends on all services
  ✗ If service fails to build → registry can't build
  ✗ Can't deploy services independently
  ✗ Circular dependency risk
  ✗ Violates microservices principles
  ✗ Unnecessary 70MB of bloat in registry JAR

Benefits:

🏗️ HOW IT ACTUALLY WORKS
═══════════════════════════════════════════════════════════════════════════════

CLIENT-SIDE REGISTRATION PATTERN:

1. Eureka Registry starts on port 8761
   └─ Just waits for services to register
   └─ Doesn't need service JARs

2. Each Microservice starts with eureka-client dependency
   ├─ Reads: eureka.client.serviceUrl.defaultZone
   ├─ Sends: "I'm catalog-service at localhost:8081"
   ├─ Eureka registers it in memory
   └─ Service is now discoverable!

3. Gateway discovers services from Eureka
   ├─ Client asks for /catalog/products
   ├─ Gateway queries Eureka: "Where's catalog-service?"
   ├─ Eureka responds: "At localhost:8081"
   └─ Gateway forwards request there

KEY: Services know about registry → Registry doesn't know about services

✅ CORRECT CONFIGURATION FOR EACH MICROSERVICE
═══════════════════════════════════════════════════════════════════════════════

Each microservice (catalog, customer, inventory, rental) needs:

1. Add to pom.xml:
   <dependency>
       <groupId>org.springframework.cloud</groupId>
       <artifactId>spring-cloud-starter-netflix-eureka-client</artifactId>
   </dependency>

2. Add to application.yaml:
   spring:
     application:
       name: catalog-service  # (or service name)

   eureka:
     client:
       serviceUrl:
         defaultZone: http://localhost:8761/eureka/

3. Add annotation to main class:
   @EnableEurekaClient
   @SpringBootApplication
   public class CatalogServiceApplication {
       public static void main(String[] args) {
           SpringApplication.run(CatalogServiceApplication.class, args);
       }
   }

4. Start the service:
   mvn spring-boot:run

DONE! Service now self-registers with Eureka!
